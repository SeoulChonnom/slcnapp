# 02. 법적 문제 · 약관 리스크

> 조사일: 2026-10-08. 이 문서는 개발 판단을 돕기 위한 정리이며 **법률 자문이 아니다.**
> 출시 전에 각 공급자와 관계 기관에 **서면으로** 확인을 받아 두는 것을 권한다.

## 1. 데이터 저장 금지 약관 — 가장 큰 리스크

### 1.1 카카오 로컬 API

| 데이터 | 저장 | 근거 |
|---|---|---|
| 장소 ID, 장소 상세 URL | ✅ 영구 저장 가능, 내부 데이터와 매핑 가능 | 데브톡 운영팀 답변(2026-05-08) |
| 장소명, 주소, 전화번호, 좌표 | ❌ "라이브 콜 only" | 같은 답변 |
| 검색 결과 좌표를 **사용자가 화면에서 확인·확정한 경우** | ❌ 저장 불가 | 데브톡 운영팀 답변(**2026-08-24**) |
| SDK 라벨을 클릭해서 받은 POI 장소명 | ❌ 저장 불가 | 같은 답변 |
| 화면에 보여줄 때마다 로컬 API를 다시 호출해 표시 | ✅ 허용 | 같은 답변 |
| 서비스가 **자체 보유한** 좌표를 카카오맵에 표시 | ✅ 허용 | 데브톡 답변(2026-05-08) |
| 캐시 | 사용자 환경 개선 목적의 짧은 캐시만 허용. 한 달이나 일 년 단위는 "저장"으로 본다 | 운영정책 제5조 20호, 데브톡 답변(약 2년 전) |

**이 기능에 미치는 영향**
- "단지명 검색 → 좌표를 DB에 저장"이라는 가장 단순한 설계는 **약관 위반**이다.
- 사용자가 직접 입력한 텍스트(단지명 등)는 API 결과가 아니므로 저장할 수 있다. 반면 **카카오 결과로 받은 주소 문자열을 사용자가 그대로 확정했을 때 저장해도 되는지는 명시된 답변이 없다**(회색지대).
  - 안전한 방법: 주소를 **행안부 도로명주소 검색 API 결과로 다시 확정**해서 저장한다(행안부 데이터는 저장할 수 있다).
- "지도를 직접 클릭해서 찍은 좌표"(검색과 무관)를 저장해도 되는지도 명시적인 답이 없다. 2026-08-24 답변이 "앞선 좌표 저장 안내를 다시 확인하라"고만 했으므로 **보수적으로 불가로 본다.**

### 1.2 네이버 Maps (NCP)
- 이용약관(2025-03-20 시행) 제7조 ⑨: 사전 동의 없이 저장, 가공, 제공할 수 없다.
- 제7조 ⑪: 결과 데이터는 받는 즉시 1회만 쓸 수 있다. "지도 좌표 데이터를 모아서 (그 이후에는 API를 호출하지 않고) 재사용하는 것은 엄격히 금지"한다.
- 네이버 지도 법적 고지: 국토교통부장관의 사전 승인 없이 지도를 복제하거나, 국외로 반출하거나, 이 지도를 이용해 다른 지도를 간행할 수 없다.

### 1.3 TMAP
- "TMAP Open API를 이용하여 얻어진 데이터는 저장 후 **24시간 이상** 사용할 수 없습니다."
  - 경로 결과는 **24시간 이내로 캐시**할 수 있는 것으로 해석된다. 카카오보다 캐시 여유가 있다.
- 같은 서비스에 여러 프로젝트를 만들어 무료 한도를 늘리는 것은 금지된다.

### 1.4 브이월드 Geocoder
- "API 요청은 실시간으로 사용하셔야 하며 별도의 저장장치나 데이터베이스에 저장할 수 없습니다." → 정부 API라고 해서 모두 저장할 수 있는 것은 아니다.

### 1.5 저장할 수 있는 출처
- **행정안전부 도로명주소 API:** 공공데이터포털에 "이용허락범위 제한 없음"으로 되어 있다.
- **SGIS(국가데이터처):** 공공누리 1유형(출처 표시)이며 저장 금지 조항이 없다. **단, 약관 제7조 ④에 따라 "영업활동"에 쓰려면 사전 승낙이 필요하다.**
- **도로명주소 위치정보요약DB:** 공공누리 1유형이다. 도로명주소법 시행령 제46조와 시행규칙 제53조에 따라 이용목적 심사를 거쳐 받는다.

### 1.6 경로 결과(도보 경로 폴리라인)
- 카카오 도보 경로 결과를 따로 저장해도 되는지는 명시된 정책을 찾지 못했다. 같은 카카오맵 API 운영정책을 적용받으므로 **로컬 API처럼 "실시간 호출, 저장 금지"로 간주한다.**
- 결과적으로 **화면을 열 때마다 호출**해야 한다. 이것이 비용(쿼터)에 미치는 영향은 03 문서 §5에서 계산한다.
- 반면 **방문 순서**(자체 알고리즘으로 계산한 결과)와 **자체 보유 좌표 사이의 직선거리**는 우리 데이터이므로 저장할 수 있다.

## 2. 위치정보법 (위치정보의 보호 및 이용 등에 관한 법률)

### 2.1 무엇이 문제가 되는가
- **개인위치정보**(특정 개인의 위치를 알 수 있는 정보)를 대상으로 하는 위치기반서비스사업을 하려면 방송미디어통신위원회에 **신고**해야 한다(법 제9조).
- 개인위치정보를 다루지 않는 위치기반서비스는 신고 대상이 아니다.
- 위치정보지원센터 안내에 따르면, 개인위치정보를 **이용자 단말 안에서만 쓰고 사업자 시스템으로 보내지 않는 경우**에는 신고 대상에서 빠진다(원문 재확인 필요).
- 소상공인이나 1인 창조기업은 제9조의2 특례가 있다. 한 해설에 따르면 사업 개시 후 1개월 안에 신고하면 된다.

### 2.2 이 기능에 적용하면

| 시나리오 | 개인위치정보 해당 여부 | 판단 |
|---|---|---|
| 매물·단지 주소와 좌표 저장 | 일반적으로 **해당하지 않는다**(사물·장소의 위치) | 저위험 |
| 사용자가 출발지를 "○○역", "주소 입력"으로 직접 고름 | 해당하지 않는다고 볼 여지가 크다(사용자가 고른 장소) | 저위험 |
| 브라우저 GPS(`navigator.geolocation`)로 현재 위치를 얻어 **지도에만** 표시 | 단말 안에서만 처리 → 신고 예외에 해당할 가능성 | 중위험(원문 확인) |
| GPS 현재 위치를 **BE 프록시로 보내 경로 API 호출** | 사업자 시스템으로 보냄 → **신고 대상일 가능성 높음** | **고위험** |
| 임장 당일 이동 궤적 기록 | 개인위치정보 수집에 해당 | **고위험** — 범위 밖 |

**권고:** 1차 범위에서는 **GPS를 쓰지 않는다.** 출발지와 도착지는 사용자가 역이나 주소로 고르게 한다. "현재 위치에서 출발" 기능은 위치정보지원센터(lbsc.kr)에 서비스 구조를 문의한 뒤 결정한다.

### 2.3 개인정보보호법
- 매물 주소와 방문 일시는 "누가 언제 어디를 보러 갔다"는 정보다. 계정과 연결되면 개인정보에 해당할 수 있다. 기존 임장 기록도 같은 성격이므로 **새로운 리스크는 아니다.** 다만 외부 API로 좌표를 보낼 때 **사용자 식별자를 함께 보내지 않도록** BE 프록시에서 걸러야 한다.

## 3. 공간정보 관련 법령

- 「공간정보의 구축 및 관리 등에 관한 법률」은 국가 기본도를 복제, 간행, 반출하는 것을 규제한다. 공급자가 승인을 받아 제공하는 **지도 SDK를 그대로 쓰는 것은 이 규제와 무관하다.**
- 금지되는 것: 지도 타일을 스크래핑하거나 저장해서 자체 지도를 만들거나, 다른 지도로 간행하는 것(네이버 법적 고지에 명시).
- 이 기능은 마커와 경로선을 SDK 위에 겹쳐 그리는 것뿐이라 **해당 사항이 없다.**

## 4. 출처 표시 · 로고 의무

| 공급자 | 의무 |
|---|---|
| 카카오맵 | 지도 SDK의 카카오 로고와 저작권 표기를 가리면 안 된다. 로고 및 디자인 가이드를 따르는 것을 권장한다 |
| SGIS | 공공누리 1유형이므로 출처 표시가 필요하다(예: "출처: 국가데이터처 SGIS") |
| 행안부 도로명주소 | 출처 표시 조건은 운영키를 신청할 때 확인한다 |
| TMAP (예비) | 확인 필요 |

→ 지도 화면 하단에 **"주소·좌표: 행정안전부, 국가데이터처 SGIS"** 같은 출처 표기 영역을 마련한다.

## 5. 비용 관련 리스크 (법적 리스크와 연결)

- **무료 쿼터가 앱 단위라는 함정:** 카카오는 계정에서 "처음 활성화한 앱"에만 무료 쿼터를 준다. 개발용 앱을 먼저 켜면 운영 앱이 유료가 된다.
- **약관 위반을 피하려다 비용이 늘어난다:** 저장을 금지하니 매번 다시 호출해야 하고, 그만큼 쿼터를 쓴다. 지도 화면을 열 때마다 도보 경로를 부르면 "열람 수 × 구간 수"만큼 호출된다.
  - 대책: 경로선은 **사용자가 "경로 보기"를 눌렀을 때만** 불러온다(lazy). 방문 순서와 직선 연결선은 기본으로 보여준다.
- **무료 한도를 넘었을 때:** 카카오는 유료 설정을 하지 않았으면 `429`로 차단된다(예상치 못한 과금은 없다). UI에서 `429`를 받으면 "직선 경로로 대신 표시"하도록 폴백을 둔다.
- **SGIS 영업활동 조항:** 지금은 개인·지인용 서비스로 보이므로 문제가 없다. 다만 **유료화하거나 광고를 붙이면** 사전 승낙이 필요하다.

## 6. 확인 요청 목록 (서면 확보 권장)

| 대상 | 질문 |
|---|---|
| 카카오 데브톡 | ① 사용자가 지도를 직접 클릭해 찍은 좌표(검색 결과와 무관)를 저장해도 되는가 ② 도보 경로 조회 결과를 세션 동안 메모리에 캐시해도 되는가 ③ 장소 ID로 단건을 조회하는 API가 있는가 |
| 국가데이터처 SGIS | 비영리 개인 서비스에서 지오코딩 결과를 영구 저장해도 되는가, 출처 표시 위치 |
| 행정안전부 주소생활공간과 | 도로명주소 검색 API 결과를 저장할 수 있는지, 트래픽 한도 |
| 위치정보지원센터 | GPS 현재 위치를 출발지로 쓰고 BE를 거쳐 경로 API를 호출하는 구조가 신고 대상인가 |
| SK open API (TMAP을 쓸 경우) | 보행자 경로 결과를 카카오 지도 위에 표시해도 되는가 |
