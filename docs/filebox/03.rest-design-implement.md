# FileBox REST 구현 결과

## 작업 범위

`docs/filebox/03.rest-design.md` 기준으로 `slcn-rest` 모듈의 FileBox 전환 영향을 반영했다.

REST production 코드는 이미 새 Spec DTO와 Aggregate Logic 시그니처로 컴파일되고 있었으므로 변경하지 않았다. 이번 작업은 HTTP JSON 계약 회귀를 막기 위한 REST 테스트 보강에 집중했다.

## 구현 내용

### Travel JSON 계약 테스트 추가

추가 파일:

```text
slcn-rest/src/test/java/com/seoulchonnom/rest/travel/TravelResourceJsonContractTest.java
```

검증 내용:

- `POST /travels` 요청의 `files` payload가 `TravelCdo.files`로 바인딩된다.
- `travelDays[].date`가 Travel day 식별자로 전달된다.
- `places[].placeKey`가 Travel place 식별자로 전달된다.
- `targetType`, `role` enum 값이 FileBox DTO로 바인딩된다.
- `PATCH /travels/{travelId}` 요청에서 기존 FileBox item `id`와 신규 item의 `id == null` 상태가 `TravelUdo.files`로 전달된다.

### Trip JSON 계약 테스트 추가

추가 파일:

```text
slcn-rest/src/test/java/com/seoulchonnom/rest/trip/TripResourceJsonContractTest.java
```

검증 내용:

- `POST /trips` 요청의 role별 `files` payload가 `TripCdo.files`로 바인딩된다.
- `LOGO`, `FIRST_MAP`, `SECOND_MAP` role이 정상 역직렬화된다.
- `files` 누락 시 `TripCdo.@NotNull`과 `CommonExceptionHandler`를 통해 400 응답이 반환된다.
- 잘못된 enum 값은 `HttpMessageNotReadableException` 경로로 400 응답이 반환된다.

## 유지한 결정

- FileBox 전용 Resource 또는 Facade를 추가하지 않았다.
- Travel/Trip Resource에 FileBox target/role/file type 검증을 중복 구현하지 않았다.
- 기존 생성 성공 응답 상태인 `200 OK`를 유지했다.
- Travel DTO에는 현재 Bean Validation 어노테이션이 없으므로 `TravelResource`에 `@Valid`를 추가하지 않았다.

## 결론

REST production 코드는 FileBox 전환을 위해 추가 수정하지 않아도 되는 상태다.

이번 단계에서는 Travel/Trip 요청의 파일 연결 source of truth가 `files` 필드임을 JSON 계약 테스트로 고정했다. FileBox는 별도 REST API로 노출하지 않고, 기존 Travel/Trip API의 요청 DTO를 통해서만 다룬다.
