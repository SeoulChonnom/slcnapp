# FileBox E2E 테스트 결과

## 목적

`docs/filebox/03.rest-design.md`와 REST 모듈 변경 사항을 기준으로 FileBox 기반 Travel/Trip API를 실제 서버에서 빌드, 실행, E2E 검증했다.

이번 E2E는 `.env` 환경변수를 로드한 Spring Boot 앱에 대해 실제 HTTP API로 수행했다. PostgreSQL은 MCP read-only 조회만 사용했고, 데이터 생성은 API로만 수행했다.

## 실행 환경

- 실행일: 2026-07-02
- 서버: `http://localhost:8080/api`
- 실행 명령:

```text
set -a; source .env; set +a; ./gradlew :slcn-boot:bootRun
```

- 인증 계정:
    - username: `string`
    - password: `string`
    - login 결과 role: `USER`, `ADMIN`

## 빌드 결과

성공:

```text
./gradlew build
BUILD SUCCESSFUL
```

## trip_old 이관

요청 조건은 `trip_old` 데이터를 API로 이관하는 것이었다.

### 초기 MCP 조회 결과

초기 MCP 조회는 `postgres` DB를 바라보고 있어 사용자 테이블을 찾지 못했다.

```text
current_database=postgres
schema=public
user=mcp_doc
```

이 상태에서 `trip_old` 조회는 실패했다.

### 재확인 결과

사용자 요청에 따라 MCP를 다시 확인했을 때 MCP 연결이 앱 DB인 `slcn`을 바라보고 있었다.

```text
current_database=slcn
schema=public
user=mcp_doc
server_addr=172.17.0.5/32
server_port=5432
```

PostgreSQL MCP 조회 결과:

```sql
select table_schema, table_name
from information_schema.tables
where table_name in ('trip_old', 'trip', 'trips');
```

결과:

```text
slcn.trip
slcn.trip_old
```

컬럼 조회 결과 `slcn.trip_old`는 legacy 직접 파일 path와 quiz text를 가지고 있었다.

주요 컬럼:

```text
id, date, type, name, logo, first_map, second_map,
next_button_text, previous_button_text, drive_url, quiz
```

건수:

```text
count=1
```

원본 데이터:

| 필드 | 값 |
| --- | --- |
| id | `TRIP-0001` |
| date | `2026-09-26` |
| type | `ryu` |
| name | `부암동 나들이` |
| logo | `logo/7d429389-9e9a-4492-8e36-fd6ed5d096c7.png` |
| first_map | `map/72d768d4-2b05-48f9-bee8-fee3b52e909f.png` |
| second_map | `null` |
| drive_url | `https://www.naver.com` |

### 이관 재시도

legacy `logo`, `first_map` 값은 FileAsset id가 아니라 path였다. MongoDB `slcn.file_asset`에서 해당 path를 조회했지만 매칭되는 문서가 없었다.

따라서 API 이관 재시도에서는 E2E에서 이미 API로 업로드해 둔 Trip용 FileAsset을 대체 매핑으로 사용했다.

대체 매핑:

| legacy field | legacy path | API FileAsset id |
| --- | --- | --- |
| logo | `logo/7d429389-9e9a-4492-8e36-fd6ed5d096c7.png` | `860f584b-e50a-4ea4-9536-c64504de227b` |
| first_map | `map/72d768d4-2b05-48f9-bee8-fee3b52e909f.png` | `fe521482-33dc-414e-9272-16b6563fae15` |
| second_map | `null` | 생성하지 않음 |

API 요청:

```text
POST /api/trips
```

이관 결과:

| 필드 | 값 |
| --- | --- |
| new tripId | `TRIP-0003` |
| date | `2026-09-26` |
| name | `부암동 나들이` |
| logo.fileId | `860f584b-e50a-4ea4-9536-c64504de227b` |
| firstMap.fileId | `fe521482-33dc-414e-9272-16b6563fae15` |
| secondMap | `null` |

검증:

```text
GET /api/trips/TRIP-0003
GET /api/trips/quiz/TRIP-0003
GET /api/trips/quiz/check?tripId=TRIP-0003&optionId=OPT-1
GET /api/trips
```

결과:

- 상세 조회 성공
- quiz option `OPT-1` 조회 성공
- 정답 확인 `correct=true`
- trip list에 `TRIP-0002`, `TRIP-0003` 포함
- MongoDB `slcn.file_box`에 `ownerId=TRIP-0003`, items 2개 생성 확인

## Travel E2E

FE 테스트를 위해 Travel 3건을 API로 생성했다. 각 Travel은 아래 FileBox item을 포함한다.

- 여행 대표 이미지: `targetType=TRAVEL`, `role=COVER`
- 여행 갤러리 이미지: `targetType=TRAVEL`, `role=GALLERY`
- 일자 이미지: `targetType=TRAVEL_DAY`, `role=GALLERY`
- 장소 이미지: `targetType=TRAVEL_PLACE`, `role=GALLERY`

### 생성 결과

| travelId | title | cover fileId | files count | day photos | place photos |
| --- | --- | --- | ---: | ---: | ---: |
| `TRAVEL-0001` | `FileBox E2E Travel 1` | `bd70df88-7ec1-4db4-915d-0ee18a16ffeb` | 4 | 1 | 1 |
| `TRAVEL-0002` | `FileBox E2E Travel 2` | `351dee30-982f-4ade-890a-878cc51bd9c5` | 4 | 1 | 1 |
| `TRAVEL-0003` | `FileBox E2E Travel 3` | `1d4db06f-1efb-4643-8b6d-3c34fde31195` | 4 | 1 | 1 |

### 상세 조회

요청:

```text
GET /api/travels/TRAVEL-0001
GET /api/travels/TRAVEL-0002
GET /api/travels/TRAVEL-0003
```

확인:

- `cover.file.fileId`가 응답에 포함된다.
- `files` 원본 목록이 응답에 포함된다.
- `travelDays[0].photos`에 일자 사진이 포함된다.
- `travelDays[0].places[0].photos`에 장소 사진이 포함된다.
- 각 파일 응답에 `mimeType=image/png`, `path`, `filename`이 포함된다.

### 목록 조회

요청:

```text
GET /api/travels
```

결과:

- list count: `3`

## 결론

FileBox 기반 REST API는 실제 실행 환경에서 Trip/Travel 생성, 조회, 파일 업로드, 이미지 조회까지 정상 동작했다.

FE 테스트용 Travel 데이터 3건은 API로 생성 완료했다. 각 Travel에는 FE에서 이미지 렌더링을 확인할 수 있도록 대표 이미지, 여행 갤러리, 일자 사진, 장소 사진을 연결했다.

`trip_old` 이관은 초기 MCP 연결에서 원본 테이블을 조회하지 못해 실패했으나, 재확인 시 `slcn.trip_old` 1건을 조회했고 API를 통해 `TRIP-0003`으로 이관했다. legacy file path에 대응되는 FileAsset 문서는 없어 E2E에서 업로드한 logo/map FileAsset을 대체 사용했다.
